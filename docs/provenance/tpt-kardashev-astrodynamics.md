# Provenance: tpt-kardashev-astrodynamics

Origin of code and designs in this crate. Reference code is read, not linked (spec §3.8).

## Ported code

None.

## Written from standard relations

- `elements.rs` (Keplerian ↔ state vector): written from the standard two-body relations (the perifocal position and velocity, the rotation Rz(Ω)·Rx(i)·Rz(ω), and the usual state-to-element formulas for h, the node vector, the eccentricity vector and the energy). The singular-case conventions are this crate's own, chosen so that each state has one element set. No reference implementation was consulted for this code; the tests check it against identities and round trips, not against another implementation.

- `matrix.rs` and `frames.rs` (perifocal rotation and RTN): the rotation is the product Rz(Ω)·Rx(i)·Rz(ω), and RTN is the triad R = r̂, N = ĥ, T = N × R, both from standard definitions. No reference code was consulted.

- `propagate.rs` (two-body propagation): the universal-variable formulation, meaning the f and g coefficients, the universal Kepler equation and the Stumpff functions. Written from the standard relations; no reference code was consulted. The tests check it against conservation laws, composition, reversal and an independent Kepler-equation solve.

- `force.rs` and `integrate.rs` (central gravity, classical RK4 and the Cowell formulation): the point-mass acceleration −μr/|r|³ and the classical fourth-order Runge–Kutta step are standard; written here from those definitions, with no reference code consulted.
- **Recalled, to verify before release:** the Moon's low-precision coefficients in `ephemeris.rs` (L′, M′, D, F, M and the terms of the six longitude, four latitude and four distance series) are the leading terms of the standard series as recalled, and are checked only against the Meeus example in the tests. The gravitational parameters `SUN_MU_KM3_S2` = 1.327 124 400 41×10¹¹ km³/s² and `MOON_MU_KM3_S2` = 4 902.800 066 km³/s² are the DE430 values as recalled. The obliquity 84 381.406″ is the IAU 2006 value as recalled. The solar radiation pressure at one AU, `SOLAR_PRESSURE_1AU_PA` = 4.56×10⁻⁶ N/m², is a commonly used value, recalled rather than read from a source. All four should be checked against their sources.
- `force.rs` (solar radiation pressure): the acceleration ν·C_R·(A/m)·P·(AU/d)²·(r − r_sun)/d and the cylindrical Earth shadow (night side, within one Earth radius of the Sun–Earth axis) are written from those definitions, with no reference code consulted. The penumbra is not modelled.
- `atmosphere.rs` (exponential density) and `force.rs` (atmospheric drag): the drag −½·C_D·(A/m)·ρ·|v_rel|·v_rel with v_rel = v − ω×r is the standard form, written from that definition; no reference code consulted. **The density table (27 rows of altitude, reference density and scale height, 0–900 km) is recalled, and must be checked against its source before release.** The continuity of the table was checked at every row boundary (within 0.01%, except 0.14% at 25 km), which catches an entry copied wrongly but not one that is consistently wrong. The Earth's rotation rate 7.292115×10⁻⁵ rad/s is the WGS 84 value, as recalled.
- `force.rs` (thrust): a constant acceleration in a fixed or prograde direction over a time window. It is a model of an acceleration, not a rocket equation; no reference code consulted.
- `visibility.rs`: the WGS 84 ellipsoid (equatorial radius 6378.137 km, first eccentricity squared 0.006 694 379 990 14, both as recalled), the geodetic-to-Cartesian formula, the elevation of a satellite above the local vertical, and the bisection search for window edges. The Earth-rotation angle is an input, not computed from time. No reference code consulted.
- `spk.rs` (SPK reader): the DAF file record, the summary and name records, the word addressing and the type-2 record layout (MID, RADIUS, Chebyshev coefficients of X, Y and Z; directory INIT, INTLEN, RSIZE, N) are written from the NAIF DAF and SPK documentation (naif.jpl.nasa.gov toolkit documents), read in this project. The summaries' packed integers are read as little-endian, the order LOCFMT `LTL-IEEE` gives; the documentation does not state the int-pair order explicitly, so this follows the usual layout and should be checked against a real kernel. No reference code consulted.
- `sgp4.rs` (near-earth SGP4): the model is the one in Vallado, Crawford, Hujsak and Kelso, "Revisiting Spacetrack Report #3", AIAA 2006-6753 (https://celestrak.org/publications/AIAA/2006-6753/), which gives the WGS-72 constants (Table 2) and the equations. The paper's code listing carries no licence and asks for citation. This implementation was written from the equations: the un-Kozai correction, the initialization of the drag and secular terms, the secular and long-period propagation, the Kepler solve and the TEME output. It is not a copy of that listing. The deep-space terms are in `sdp4.rs`, written in the same way from the report's equations for the lunar-solar periodics, the resonance coefficients and the resonance integrator. Its integrator starts from the epoch on each call, where the report's keeps state between calls; the two give the same grid, up to the report's own round-off. The Greenwich sidereal time is the report's polynomial, taken from the day count since J2000 to keep its precision. The printed deep-space outputs used for tests are cited as facts. Residuals against the printed outputs (position, km): most of the 22 deep-space and Report #3 cases agree to about 5×10⁻⁹ km, which is the precision of the printed values. Five cases reach 2×10⁻⁶ to 1.7×10⁻⁵ km (09880, 21897, 16925, 23333, 23599), and 08195 reaches 2.3×10⁻⁴ km at 2400 minutes. The high-eccentricity resonant cases are the largest. I checked the resonance coefficients for each eccentricity branch against the paper's text, and changing the sidereal angle by 10⁻⁹ rad does not move the residual, so the cause is still open. Also ruled out: the Kepler iteration limit (raising it from ten to fifty steps leaves every residual unchanged), and the constants (each was checked against the paper's text). Not yet tried: the report's other code versions, which the paper says differ in details such as the Lyddane choice, and an independent implementation to compare against. The TLE fields are read by whitespace token, because the verification element set's column alignment differs from the standard. The test values are the paper's printed outputs for satellites 00005, 06251, 28057, 28350, 22312 and 29238, and the paper's element sets and trap times, cited as facts, not copied files; the verification data file is not in the repository.
- `ephemeris.rs` (Sun): the low-precision series for the Sun's mean longitude, mean anomaly, equation of centre and distance (constants 280.460, 357.528, 0.9856474, 0.9856003, 1.915, 0.020, 1.00014, 0.01671, 0.00014). These are the standard low-precision coefficients, entered from memory and checked only by the J2000 values and the annual cycle in the tests, not against a published table. The astronomical unit (149 597 870.7 km) is the IAU 2012 value. No reference code consulted.
- `lambert.rs` (Lambert's problem): the universal-variable formulation, with A = ±sqrt(r1·r2·(1 + cos Δν)), y(z), the time residual F(z), and the f, g and ġ coefficients. Written from the standard relations; no reference code consulted. The sense convention is this crate's own. Tests check it on exact circular arcs and by round trip through the propagator.
- `manoeuvre.rs` (Hohmann, bi-elliptic and plane change): the burns follow from the vis-viva equation and the standard transfer ellipses. Written from those relations; no reference code consulted.
- `force.rs` (J2 zonal perturbation): the acceleration −(3/2)·J2·μ·R²/r⁵·(x(1 − 5z²/r²), y(1 − 5z²/r²), z(3 − 5z²/r²)) and the secular nodal rate −(3/2)·n·J2·(R/p)²·cos i are standard expansions, written from those forms. The constants are WGS 84 (NGA.STND.0036): equatorial radius 6378.137 km and J2 = 1.08262668355×10⁻³ (EGM96, which WGS 84 adopts). **These values were entered from memory, not read from the document, and must be checked against the source before release.** No reference code was consulted.
- `force.rs` (`ZonalHarmonics`, degrees 2 to 4): the acceleration (μ/r³)·S₁·(x, y, z) + (μ/r⁴)·S₂·(zx, zy, −(x²+y²)), with S₁ = Σ(n+1)Jₙqⁿ Pₙ(s) and S₂ = Σ Jₙqⁿ Pₙ′(s), derived from the geopotential expansion. Tests: the J2 term matches `J2Zonal` to 1e-12; the closed form matches a finite-difference gradient of the potential for J2, J3 and J4 (1e-6); the J3 equatorial closed form; the parity of the odd harmonic. **The J3 and J4 constants are not bundled.** Two searches for the NGA WGS 84 / EGM96 values returned JGM-3 figures (J3 ≈ −2.5324×10⁻⁶, J4 ≈ −1.6193×10⁻⁶) and the values recalled for EGM96 (−2.53265648533×10⁻⁶, −1.61962159137×10⁻⁶), which differ at about 10⁻⁴ relative, and the shell could not reach the NGA documents to settle it. Until one is checked against the EGM96 coefficient file or NGA.STND.0036, the caller supplies them.

- `symplectic.rs` (velocity Verlet): the standard second-order Störmer–Verlet update (half-kick, drift, half-kick, written as the position update x + v·h + a·h²/2 and the velocity update v + (a₀ + a₁)·h/2), written from that definition. No reference code consulted. The bounded-energy property is the method's known behaviour for position-only forces; the tests measure it on the two-body problem rather than assume it.

- `adaptive.rs` (Dormand–Prince 5(4)): the Butcher tableau of the Dormand–Prince pair, and its step-size rule, written from the published coefficients as recalled. The tests check them against the analytic two-body solution: a wrong coefficient would lose the fifth-order accuracy and fail them. **The coefficients are recalled and should be checked against the published table before release.** No reference code was consulted.

- `time.rs` (epochs, UTC and Julian dates): the constants are the definitions (TT − TAI = 32.184 s; J2000 is 2000-01-01 12:00 TT, JD 2451545.0). The calendar conversions use the civil-date algorithm of Howard Hinnant (integer days from 1970-01-01), written here from the published description; no code was copied. The leap-second fixture in `tests/time.rs` holds the IERS TAI − UTC values as recalled; it is test data, and should be checked against IERS Bulletin C before the test values are relied on. The crate bundles no leap-second data.
